About this project

How the Charity Events website works

This site is the client-side website for the PROG2002 Web Development II charity events case study. It is a fully dynamic website: every event, category and registration you see was fetched from a REST API at the moment the page loaded.

The technology

Front end
Angular (standalone components, signals, RxJS, reactive forms)
Back end
Node.js with Express, exposing a RESTful API
Database
MySQL — categories, events and registrations
External API
Open-Meteo, proxied through our own weather endpoint so the weather codes can be translated and cached

What each page does

  • Home Loads the upcoming Active events and the category list from the API.
  • Search Sends the keyword, category, status and sort choices to the API and renders exactly what comes back — the filtering happens in SQL, not in the browser.
  • Event details Fetches one event together with every registration for it, sorted by the date the tickets were purchased (newest first), and adds a seven-day forecast.
  • Registration Confirms the selected event, validates the visitor's details, then posts a new registration and shows a confirmation reference.

Data flow, step by step

  1. A visitor opens a page and Angular calls one of the endpoints above through HttpClient.
  2. The request reaches the Express API, which validates the query and builds a parameterised SQL statement.
  3. MySQL returns the rows, and the API shapes them into JSON with consistent field names and number types.
  4. An RxJS subscription in the page component receives the response and writes it into an Angular signal.
  5. The template re-renders automatically, showing the results, or a loading spinner, or an empty state.
